# 项目目录模板

> **用途**：每本书一个自包含目录。任何人（或模型）拿到这个目录，就能接续工作——不需要额外解释。
> **原则**：**文件名即用途**，编号即顺序。不要用"草稿""新建文件夹""最终版2"这类名字。

---

## 一、标准结构

```
{{书名}}\
├─ 00_项目卡.md                 ← 稳定元信息（题材/篇幅/文风锚/硬约束）· 内核文件 01
├─ 01_设定\
│   ├─ 世界观.md                 ← 活文档
│   ├─ 力量体系.md
│   ├─ 金手指规格书.md            ← 必须含【能力边界】与【代价】，缺此两项等于没有约束
│   └─ 文风锚.md                  ← 可选；格式见内核文件 07 · §三
├─ 02_人物\
│   ├─ 人物表.md
│   └─ 角色卡\
│       └─ {{角色名}}.md          ← 五维 + 语言指纹 · 模板见内核文件 07 · §一
├─ 03_大纲\
│   ├─ 总纲.md
│   ├─ 分卷大纲.md
│   └─ 细纲\
│       └─ 第{{NNN}}章.md         ← **6 字段**，缺一即不合格 · 准入检查见内核文件 04 · §四
├─ 04_正文\
│   └─ 第{{NNN}}章.md
├─ 05_台账\
│   ├─ 伏笔台账.md                ← 埋设 ↔ 销账 对照，未销账数写进状态文件
│   ├─ 连续性台账.md              ← 时间线 / 数值 / 称谓 / 状态变更回填
│   └─ 去AI味规则台账.md           ← **跨书**资产的**项目内只读快照**，见 §三
├─ 06_日志\
│   └─ 动作日志.md                ← append-only · 内核文件 06
├─ 98_生成方式声明.md             ← 发布前生成 · 模板见内核文件 08
└─ 99_状态\
    └─ state.json                ← 机读状态 · 内核文件 02
```

> **`98_生成方式声明.md` 不是可选项**。它是法规《标识办法》第十条在产出物上的落点：
> 没有它，发布时无法回答"哪些章是 AI 生成的"。**字段规则见内核文件 08，本文件只规定位置。**

> 上表中的「内核文件 NN」指本文档同级的 `10_内核\` 目录下的文件。**内核是通用的（所有书共用一份），项目目录是每本书各自的**——不要把内核文件复制进项目目录，那会造成多份副本。

## 二、创建顺序（不要跳步）

| 步 | 动作 | 完成判据 |
|---|---|---|
| 1 | 建目录骨架 | **9 个目录**存在（7 个顶层编号目录 ＋ `02_人物\角色卡`、`03_大纲\细纲` 这 2 个嵌套目录） |
| 2 | 写 `00_项目卡.md` | 篇幅参数与文风锚已填，无 `{{占位符}}` 残留 |
| 3 | 写 `01_设定\` | 金手指规格书含【能力边界】与【代价】 |
| 4 | 写人物卡（至少主角 1 张） | 能回答"他**绝对不会**做什么"；模板见内核 07 §一 |
| 5 | 写第一章细纲并过准入检查 | 内核 04 §四 的 6 项"必须"全部满足 |
| 6 | 初始化 `99_状态\state.json` | 8 个必填字段齐全，`gates` 全为 `pending` |
| 7 | 初始化 `06_日志\动作日志.md` | 已写入第一条"项目初始化" |
| 8 | **过 G1 立意闸门** | 用户签 `G1 = passed` 或明确 `waived` |
| 9 | 再开始写正文 | — |

> **第 6 步不能省**。先有状态文件再写正文，与先写正文再补状态，代价差一个数量级——后者几乎必然丢字段。
> **第 4、5 步也不能省**：它们是 Author 开工的必备输入，跳过会直接触发"报缺停笔"。

## 三、`05_台账\去AI味规则台账.md` 的定位（**必须理解，否则会分裂成两份口径**）

去 AI 味规则台账是**跨书资产**（换书、换平台都不变），因此：

| 问题 | 答案 |
|---|---|
| 权威在哪？ | **在 `30_台账\`**（跨书共用），**不在**本项目的 `05_台账\` |
| 那项目里这份是什么？ | **只读快照**——写下"本书写作期间，台账处于哪个版本、生效规则多少条" |
| 为什么要有它？ | 让一本写完的书**可复现**：半年后想改某章，能知道当时用的是哪一版规则 |
| **禁止** | ❌ 在项目内这份里**新增/修改规则**——改了就与权威分裂，此后两处必然漂移 |

**项目内这份的内容只有三行**：台账版本号、生效规则数、快照时间。多一个字都是隐患。

## 四、命名与版本纪律

1. **章号一律三位补零**：`第007章.md`。理由：不做补零时，文件列表里 `第10章` 会排在 `第2章` 前面，人工核对时极易漏章。
2. **不要出现"最终版"**：要保留旧版就写日期（`第012章_20260919.md`），**日期比"最终"可信**。
3. **删除要留痕**：删掉一个设定或一章时，先在 `06_日志\动作日志.md` 记一行，再删。
4. **不要改名**：改名会让所有既有引用失效。要改就在文件内标注"原名：xxx"。

## 附：本模板的已知边界

1. **本模板假设单人创作**。多人协作需要额外约定（谁改了什么），本模板未覆盖。
2. **`角色卡\` 用一角色一文件**，角色数超过 30 时会变重；届时改为按卷分目录，但**不要合并成一个大文件**（大文件无法逐角色引用）。
3. **本模板不强制版本控制**。但若你用 Git，**不要把 `99_状态\state.json` 加进忽略列表**——它恰恰是最该留痕的文件。
4. **目录数量是 **9 个目录** 而非 8 个**（含 2 个嵌套）。若你的工具显示不同数目，**以本表为准**核对，不要按"数字看着差不多"放过。
