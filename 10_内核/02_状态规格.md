# 状态规格（state.json ＋ 纯对话状态块）

> **用途**：让系统在换会话、换工具、换人之后**不失忆**。这是本系统与"提示词库"的根本区别。

---

## 〇、唯一原则：**每个字段只有一个家**

系统的信息分三类，各有唯一存放位置：

| 类别 | 例子 | **唯一存放位置** | 变更频率 |
|---|---|---|---|
| **标识** | `book_id` | **两处都有**（见下注） | 从不 |
| **稳定元信息** | 书名、题材、篇幅参数、文风锚、硬约束 | **项目卡** | 极少 |
| **易变状态** | 进度、闸门、校准、台账版本、未销账数 | **状态文件 / 状态块** | 每章 |

> **`book_id` 是刻意的例外**：它同时出现在项目卡与状态文件里，因为它是把两边**关联起来**的键——少了它，两个文件无法证明属于同一本书。**除它之外，任何信息都不得在两处重复存放。**

**为什么这条原则要紧**：重复存放的信息**必然漂移**。漂移之后，读的人不知道以哪份为准，于是两份都开始被怀疑，最终两份都不用。

> ⚠️ **因此：`state.json` 里不存放书名、题材、篇幅、文风锚。** 需要这些时去读项目卡。这看起来"少了很多字段"，但正是它保证了不会出现"项目卡说 500 章、state.json 说 400 章"这种无法裁决的矛盾。

---

## 一、字段定义（**8 个必填字段**，缺一不可）

| 字段 | 必填 | 含义 | 取值/说明 |
|---|---|---|---|
| `schema_version` | ✅ | 状态格式版本 | 当前 `1`。格式演进时，旧项目不至于直接报废 |
| `book_id` | ✅ | 关联键 | 必须与项目卡 §一 的 `book_id` **完全一致** |
| `progress` | ✅ | `卷` / `章` / `已完成` | **`已完成` 的定义见 §二** |
| `gates` | ✅ | `G1`／`G2`／`G3` 的状态 | **含义与规则见 `03_闸门规则.md`**；取值限于 `pending`/`passed`/`waived` |
| `calibration` | ✅ | `零改动章数` / `上次回检` / `回检结论` | G3 松紧的依据，也是防自欺的依据 |
| `model_map` | ✅ | 三个人格当前所用模型 ＋ 接入方式 ＋ 探测结果 | 决定"能不能给参数级建议" |
| `open_loops` | ✅ | `未销账伏笔` / `待补设定` | 长篇最大崩坏源 |
| `ledger` | ✅ | 去 AI 味台账的 `版本` ／ `生效规则数` | 让"训练累积"可追溯 |

> **不设可选字段**。缺值必须显式写 `null` 或 `0`，**不允许整个键消失**——键消失与"值为空"在读取时无法区分，这正是数据静默丢失最常见的形态。

### §二 `progress.已完成` 的确切定义

**`已完成` = 已通过 G3 闸门的章数**，不是"已写出的章数"。

理由：`章` 与 `已完成` 若都表示"写出来了"，两个字段永远相等，等于只有一个字段。
两者的差值**本身就是信息**：`章 = 12 / 已完成 = 11` 表示**第 12 章写完但还没过审**——这正是最需要被看见的状态。

## 三、文件载体：`state.json`

```json
{
  "schema_version": 1,
  "book_id": "guize-xiufushi",
  "progress": { "卷": 1, "章": 12, "已完成": 11 },
  "gates": {
    "G1": { "status": "passed", "by": "用户", "at": "2026-09-19T10:00:00+08:00" },
    "G2": { "status": "waived", "by": "用户", "at": "2026-09-19T11:20:00+08:00" },
    "G3": { "status": "pending", "by": null, "at": null }
  },
  "calibration": { "零改动章数": 3, "上次回检": null, "回检结论": null },
  "model_map": {
    "author": { "model": null, "access": null, "probe": null },
    "reader": { "model": null, "access": null, "probe": null },
    "scout":  { "model": null, "access": null, "probe": null }
  },
  "open_loops": { "未销账伏笔": 2, "待补设定": 1 },
  "ledger": { "版本": "v0", "生效规则数": 0 }
}
```

- `access` 取值：`api` / `client` / `gateway` / `unknown`。
- `probe` 记能力探测结果（参数能否调节）；为 `unknown` 时**不得给参数级建议**。
- `model_map` 初始全为 `null` 是**刻意的**：宁可显示"未知"，也不要默认填一个没核实过的值。

---

## 四、对话载体：状态块（11 行）

**用于只有一个对话框的环境。** 每轮结束由用户复制，下一轮开头粘回。

````
```yaml
# ==== 状态块 v1 ====
# 【执行者注意】先校验：下列任一键缺失 → 停止并指出缺了哪个键，不要用默认值补。
schema_version: 1
book_id: guize-xiufushi
progress: {卷: 1, 章: 12, 已完成: 11}
gates: {G1: passed, G2: waived, G3: pending}
calibration: {零改动章数: 3, 上次回检: null, 回检结论: null}
model_map: {author: 未知/client, reader: 未知/client, scout: 未知/gateway}
open_loops: {未销账伏笔: 2, 待补设定: 1}
ledger: {版本: v0, 生效规则数: 0}
# 稳定信息（书名/题材/篇幅/文风锚）见 00_项目卡.md，此处不重复
# ==== 状态块结束 ====
```
````

### 与 `state.json` 的差异（仅两处）

| 项 | `state.json` | 状态块 | 说明 |
|---|---|---|---|
| `gates` 的 `by` / `at` | 保留 | **不写** | **不是省略，是分工**：通过人与时间的权威在 `06_日志\动作日志.md`（append-only，天然带时间戳）。状态块只回答"现在过没过" |
| `model_map` | 完整对象 | `人格: 模型/接入` 一行 | 只为可读性 |

> **关于"缺键校验"**：纯对话环境里没有程序去读这个块，**读它的是模型**。所以校验指令必须**写在块本身里**（上面第 2 行），而不是写在旁边的说明里——说明不会跟着块被复制走。这是本规格最容易做错的一点。

## 五、闸门状态的合法取值与迁移

> 闸门三态（3 个取值）的含义、谁有权设置、以及欠债的显示规则，见 `03_闸门规则.md` §二 与 §四。本节只规定**状态字段怎么写**。

| 状态 | 含义 | 谁有权设置 |
|---|---|---|
| `pending` | 待审（**包括"还没轮到审"**） | 系统可自动设置 |
| `passed` | **用户本人**审过并放行 | **仅用户** |
| `waived` | **用户主动放弃**审查 | **仅用户** |

**非法迁移（必须拒绝执行并在输出中报错）**：
- `pending` → `passed` 由系统自动完成（**这是本类系统最常见的自欺**：把"没审"变成"审过了"）
- 超时自动 `passed`
- `waived` 被后续自动改写为 `passed`

> 闸门欠债的显示规则（谁该提示、提示多频繁）见 `03_闸门规则.md` §四。

---

## 六、写入纪律（四条，不可省）

1. **幂等**：同一轮重复写入不产生副作用。依据＝`唯一任务标识`（建议 `轮次-章号-动作`，如 `r012-ch012-draft`）。
2. **先写日志，再改状态**：崩溃时可以从动作日志恢复到最后一致状态。顺序颠倒会出现"状态说改了、日志说没改"的不可解局面。
3. **整块替换**：状态块**必须整块复制**。部分粘贴会让未粘贴的字段**静默回退到旧值**。
4. **字段消失即错误**：读取时若发现某必填键不存在，**报错并停止**，不要用默认值补。补默认值等于把"数据丢了"伪装成"从没设过"。

---

## 附：本规格的已知边界

1. **纯对话环境下，纪律靠使用者的提示词与模型的遵从度**，技术上无法强制。它是**防失误**机制，不是**防作弊**机制。
2. **`gates` 的 `by`/`at` 在两种载体里形态不同**（见 §四）。这是刻意的分工，但意味着"只看状态块无法知道谁在什么时候批的"——需要时查动作日志。
3. **本规格不校验状态与真实产物的对应关系**（例如 `章 = 12` 时第 12 章的文件是否真的存在）。这属于脚本层的检查，阶段一没有。
