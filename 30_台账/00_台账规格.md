# 去 AI 味规则台账 · 规格

> **性质**：本台账是**跨书资产**，独立于任何单本书、任何平台。
> **唯一目的**：把用户"每次改稿"这个动作，变成**可累积、可执行、可回退**的规则资产。
>
> **为什么必须独立成册**：系统内外有 5 处涉及"去 AI 味"的知识（详见 §六）。它们**各有一份词表、互不知晓**。若不定唯一权威，用户每一次的训练结果都会被写进其中一个，而另外几个仍按自己的旧规则工作——**训练不会累积，只会新增第六份口径**。

---

## 一、规则条目字段（**11 个**，缺一不可）

| 字段 | 说明 | 为什么必须有 |
|---|---|---|
| `规则ID` | `DA-0001` 递增 | 可被引用、可被废止、可被追溯 |
| `类型` | 词 / 句式 / 结构 / 标点 / 节奏 | 不同类型要用不同方式检测 |
| `规则` | **可判定的**表述 | 写"要自然一点"等于没写 |
| `判定级别` | **硬禁** / 慎用 / 偏好 | 三档混用会让检测结果失去意义 |
| `作用范围` | 全书 / 仅对话 / 仅旁白 / 仅战斗章 / 仅开篇 | 同一个词在旁白是问题、在对话可能是特征 |
| `证据` | **用户原话** ＋ 出处（章/行/日期） | 没有证据的规则，三个月后没人敢删 |
| `发现次数` | 独立出现的次数 | 升级判据 |
| `首次记录` | 日期 | 判断规则的历史 |
| `最近命中` | 日期 | 判断规则是否已过时 |
| `状态` | **观察** / 生效 / 废止 | 见 §二 |
| `误伤风险` | 低 / 中 / 高 ＋ 说明 | 高风险规则上检测前必须人工确认 |

> **计数口径**：上表 11 行 ＝ 字段（**11 个**）。台账表格必须同样是 11 列——**不要把 `首次记录` 与 `最近命中` 合并成一格**，合并后计数就对不上了。

### 一.1 最小必填子集（**新增 · 回应"11 字段是无效复杂度"的审查意见**）

审查者指出："8 个必填字段／11 字段台账在空台账阶段像摆设，且逐条填满负担过重。"该意见**成立**。
处置不是删字段（删掉将来加回时历史数据缺失），而是**把"字段存在"与"字段当下必须填"分开**：

| 档 | 字段 | 要求 |
|---|---|---|
| **必填（4 项）** | `规则ID`、`规则`、`判定级别`、`证据` | 新增一条规则时**必须**当场填齐。缺任一项 → **该条不成立**，不得入库 |
| **自动（2 项）** | `首次记录`、`状态` | 由流程自动写入（`状态` 一律先写 `观察`，见 §二 机制 1） |
| **随用随填（5 项）** | `类型`、`作用范围`、`发现次数`、`最近命中`、`误伤风险` | **允许留空**（写 `—`）。留空不得被视为"条目不合规"；但 `误伤风险` 在**该规则首次上检测器前必须补**，否则不得启用 |

**收益**：新规则的**实际填写成本从 11 项降到 4 项**，同时保留完整 schema（将来升级不用迁移）。
**代价（明写）**：留空的 `作用范围` 会被默认为"全书"，这可能放大误伤 —— 所以**留空状态在检测器报告里必须显式标出**，不允许静默按全书处理。

> **本节的自我约束**：如果日后发现"5 项随用随填"长期全部为空，说明它们确实无用，**届时应删字段而非继续留着**。留着不填的字段，与没有字段一样，只会让人以为系统更完备。


### 规则要写成"可判定"的样子

| ❌ 不可判定 | ✅ 可判定 |
|---|---|
| 文笔要更自然 | `"仿佛……一般" 的比喻句式` |
| 少用形容词 | `连续两句以上使用四字形容词短语` |
| 对话太书面 | `对话中出现"因此""从而""基于此"这类连接词` |
| 节奏要快 | `单段超过 6 行的环境描写，且未推进情节` |

> **判据**：把规则交给两个人，**他们对同一段文本能否得出一致的"命中/未命中"结论**？不能，就再改。

## 二、防过度拟合机制（**本规格最关键的一节**）

**要防的具体失败**：用户指出一次"某个词很烦"，系统就把全书该词全判错，**包括那些用得对的地方**。用户于是不再信任检测结果，台账随之废弃。

| # | 机制 | 具体做法 |
|---|---|---|
| 1 | **默认进「观察」** | 用户第一次指出 → 状态 = `观察`，检测器**只提示、不计失败** |
| 2 | **升「生效」需两个条件之一** | ① 在**不同章节**独立出现 ≥2 次<br>② 用户明说"**这个绝对不要用**"（此时可直接定「硬禁」） |
| 3 | **反例优先** | 检测器命中、但**用户保留了它** → 记为该处"用户容忍"，并**下调该规则强度** |
| 4 | **反向验证（上线前必做）** | 新规则先跑**用户自己写的正文**。若在用户手写段落**大量命中**，说明规则错了——把"个人风格"当成了"AI 味"，**必须改规则，不是硬套** |
| 5 | **单章不外推** | 只来自一章的观察，**绝不升为全书硬禁** |

> **第 3 条的依据**：**假阳性比漏报更贵。** 漏报只是让人少发现一个问题；假阳性会让人**去修改本不需要修改的正确文本**。两者代价不对称，所以默认策略偏向"宁漏勿错"。

### 强度可以下调，也可以上调

- 下调：命中但被保留 → 降一档（硬禁 → 慎用 → 偏好）
- 上调：同一规则被反复确认 → 升一档，**但必须记录升级依据**
- **废止**：规则不再适用（用户风格变了、题材变了）→ 状态改 `废止`，**条目保留不删**（删掉就无法解释历史上为什么那样改）

## 三、检测器的行为边界

| 做 | **不做** |
|---|---|
| 报告命中位置（文件 ＋ 行号 ＋ 原句） | ❌ **自动改写** |
| 区分「硬禁」（失败）与「偏好」（提示） | ❌ 把「偏好」当失败 |
| 报告**规则覆盖率**与命中统计 | ❌ 用"命中数下降"当作"质量提升"的证明 |
| **台账为空时明确报警** | ❌ 空台账静默通过 |

### 为什么检测器不自动改写

自动改会**掩盖判断错误**——改完之后，没人再去核对"这条规则本身对不对"，只见"问题消失了"。而且它制造"改完了就没事了"的错觉。

**检测器的价值是让你更快看到问题，不是替你做决定。**

### 为什么"命中数下降"不能证明质量提升

命中数下降有三种原因：① 确实改好了 ② 规则被误改弱了 ③ 检测器坏了。
**只看命中数无法区分这三者。** 所以必须同时看**覆盖率**（多少条规则真的跑到了）——覆盖率下降时，命中数下降是假信号。

## 四、法规划线（不可越线）

### 4.1 义务不因去 AI 味而消失

《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号，2025-03-07 印发，**2025-09-01 施行**）**第十条**：

> 第一款：用户使用网络信息内容传播服务发布生成合成内容的，**应当主动声明**并使用服务提供者提供的标识功能进行标识。
>
> 第二款：任何组织和个人不得恶意删除、篡改、伪造、隐匿本办法规定的生成合成内容标识，**不得为他人实施上述恶意行为提供工具或者服务**，不得通过不正当标识手段损害他人合法权益。

**对本台账的两条直接约束**：

1. **「去 AI 味」≠「可以不声明」。** 让文字读起来更像人写的，**不改变它仍是 AI 生成内容**这一事实。
2. **本台账禁止登记**任何以"规避平台 AI 检测"为目的的规则。此类需求**应被拒绝并说明理由**，不允许"先记下来再研究"。
   —— 第二款是这一条的直接法律依据：**为他人隐匿标识"提供工具或者服务"本身即被禁止**。

台账中的规则**只服务于写作质量**（读起来更像人写的、更少套路腔），**不服务于规避识别**。这两件事在动机上完全不同，在表述上必须分清。

### 4.2 表述纪律（防止被误读）

写"目的"与"效果"时，**不得**使用下列措辞：`以假乱真`、`无法识别`、`骗过检测`、`不会被认为是 AI`。

**正确表述**：`减少套路化表达，让文本读起来更自然`。

> **为什么要专门写这条**：即使本意是"提升可读性"，"让 AI 文字更像人写的"这个说法在外部审查视角下**与规避识别在效果上重叠**。**措辞本身就会成为证据**，所以必须主动切割。

### 4.3 批量生产护栏

本系统**不为"生成一批没人看过的内容然后直接发出去"提供便利**。具体约束：

- **每一章都必须过 G3 闸门**（见 `10_内核\03_闸门规则.md`）。闸门状态为 `pending` 的章节**不得计入已完成**。
- **不得**以"先跑 100 章再统一看"的方式绕过闸门。若确实要批量生产，**必须先明确写下抽样回检方案**（抽几章、谁来读、发现问题怎么回溯）。
- 台账**不提供**任何"提高产能"类规则——它只服务于**质量**。

## 五、数据与隐私

台账要求用户提供**本人改写的定稿**与**本人正文**作为语料。这些是个人创作内容，需明确以下几点：

| 项 | 约定 |
|---|---|
| 存储位置 | **本地文件**（本目录）。**不上传、不外发、不用于任何模型训练** |
| 内容范围 | 只收语料本身（文本片段 ＋ 用户的判断理由）。**不要写入**账号、联系方式、身份证件、住址等个人信息 |
| 删除 | 用户可随时删除任一条目；**删除后不保留副本** |
| 跨境 | 不涉及——本台账不联网 |

> **若你日后接入了任何云端服务来跑检测**，必须在这张表里补上该服务的名称与数据流向，**否则本条款失效**。

## 六、版本管理

| 项 | 规则 |
|---|---|
| 版本号 | `v0`（空台账）→ 每次批量新增/调整升一位小数，重大重构升整数位 |
| 每次变更必须记 | 时间、变更类型、涉及规则ID、依据 |
| 项目内快照 | 每本书的 `05_台账\去AI味规则台账.md` 只写**版本号 ＋ 生效规则数 ＋ 快照时间**三行。**禁止在项目内那份里新增或修改规则** |
| 回退 | 变更前保留上一个版本（台账文件复制一份，改名带日期） |

## 七、与其余 5 处模块的关系（**必须理解，否则必然漂移**）

| 模块 | 位置 | 新定位 |
|---|---|---|
| **本台账** | `30_台账\` | ✅ **唯一权威**。所有规则在此生效 |
| `de-ai-guide.md` | `fanqie-blockbuster-forge\references\` | 降为**规则来源**。其 §〇 是"需要什么语料"的说明入口；收到语料后**写入本台账**，不在该文件内生效 |
| `humanizer` | 技能 | 降为**规则来源**（英文语料，抽取时须标注来源） |
| `unclecheng-reduce-ai-perception-v2` | 技能 | 降为**规则来源**。⚠️ **该模块名含"降低 AI 被感知度"字样** —— 本系统**只抽取其句式与用词条目**，**不调用、不继承其任何规避检测功能**。抽来的条目必须逐条过 §四 的法规划线 |
| `libai` | 技能 | 降为**规则来源** ＋ **可复用的检索引擎参考** |
| `write` | 技能 | 降为**规则来源**（标点类规则） |

**"降为规则来源"的含义**：从它们那里可以**抽取条目**，抽来的条目必须**带来源标注**（例：`来源：libai/banned-words.md`），并**在本台账内独立生效**。
**它们不再单独作为判据使用**——即：一次交付的对错，只由本台账决定。

> **不删除这些模块的理由**：它们含有可复用的语料与引擎，删除是净损失。**问题不是它们存在，而是它们"各自生效"。**

## 八、接收训练的入口（用户后续提供语料时照此办）

| 输入形式 | 优先处理 | 能推出什么 |
|---|---|---|
| **正负对照**（同一段的 AI 原稿 + 用户改写定稿） | ⭐ **最高价值** | 能反推出**改写动作**（不是特征词） |
| 用户本人的正文（≥3 章，含对话与打斗各一） | ⭐ 必做 | 提取**个人风格基线**，防止把用户风格判成 AI 味 |
| 负面样本 ＋ 用户的**原话理由** | 高 | 理由比样本更重要——理由决定规则怎么写 |
| 词句黑名单 | 中 | 能加词，**反推不出句法规则** |

### 处理流程（六步）

1. **抽取**：从正负对照里提取**用户做了什么动作**（打散句式／换叙述入口／删解释／加独有细节／改对话／破均匀）
2. **成条**：每个动作写成一个**可判定**的规则条目，证据＝用户原话 ＋ 出处
3. **入「观察」**：一律先进观察状态
4. **反向验证**：把新规则跑**用户自己写的正文**——大量命中则改规则
5. **定强度**：按 §二 的判据定档
6. **记录**：写入变更记录，升版本号

> **只有黑名单时，不做阈值校准。** 黑名单能加词，但**反推不出句法规则**，也**识别不了假阳性**——强行校准会得到一份看起来很完整、实则基于猜想的规则表。

## 附：本规格的已知边界

1. **台账质量取决于用户投入的语料质量**。系统不能凭空知道"什么算 AI 味"——它只能从用户的真实判断里学。
2. **阶段一无自动检测器**。本阶段的台账是**给人读的规则表**；脚本化检测在下一阶段，且脚本只能执行已写成"可判定"形式的规则。
3. **"误伤风险"评级是主观估计**，不是统计结果。它只用于决定"上检测前要不要人工过一遍"。
4. **本规格引用的法条原文已逐字核对**（来源：中国网信网），但**本规格不构成法律意见**。具体个案是否需要声明、是否构成违规，由平台与主管部门认定；如涉及实际争议，应咨询执业律师。
